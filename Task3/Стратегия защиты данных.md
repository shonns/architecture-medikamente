# Стратегия защиты данных

## Классификация данных

| Категория данных                | Состояние         | Чувствительность         | Профиль риска                | Необходимость защиты                |
|----------------------------------|-------------------|--------------------------|-------------------------------|-------------------------------------|
| Персональные данные (PII)        | В покое, в передаче| Высокая                  | Утечка, несанкционированный доступ | Требования 152-ФЗ, репутационные риски |
| Медицинские данные               | В покое, в передаче| Критическая              | Утечка, неправомерная обработка     | Законодательство, доверие клиентов     |
| Финансовые данные                | В покое, в передаче| Высокая                  | Мошенничество, утечка               | Законодательство, финансовые потери    |
| Технические и служебные данные   | В покое, в передаче| Низкая                   | Нарушение работы, инсайдерские риски | Стабильность работы  |

## Инструменты защиты

| Данные                | Инструменты защиты                                                                                   |
|-----------------------|-----------------------------------------------------------------------------------------------------|
| Персональные данные   | Шифрование (AES-256), TLS/SSL для передачи, RBAC/ABAC, маскирование, токенизация, DLP               |
| Медицинские данные    | Шифрование (AES-256), TLS/SSL, строгий контроль доступа, тегирование, аудит, автоматическое удаление |
| Финансовые данные     | Шифрование, токенизация, TLS/SSL, контроль доступа, журналирование, PCI DSS                         |
| Технические данные    | Аудит, контроль доступа, мониторинг, резервное копирование                                          |


## Автоматизированный контроль

- **DLP-системы** (Data Loss Prevention) — предотвращение утечек данных.
- **SIEM** (Security Information and Event Management) — мониторинг событий безопасности.
- **Системы аудита и журналирования** — отслеживание доступа и изменений.
- **Системы управления ключами** (KMS) — автоматизация ротации и хранения ключей.
- **Системы тегирования и классификации** — автоматическое присвоение тегов и политик безопасности.

## Реестр программных и аппаратных средств

| Средство                        | Назначение                                   |
|---------------------------------|----------------------------------------------|
| BitLocker, VeraCrypt            | Шифрование данных на дисках                  |
| TLS/SSL                         | Защита данных при передаче                   |
| HashiCorp Vault, Azure Key Vault| Управление ключами и секретами               |
| DLP-системы (Symantec, McAfee)  | Предотвращение утечек данных                 |
| SIEM (ELK, Splunk, ArcSight)    | Мониторинг и анализ событий безопасности     |
| RBAC/ABAC в приложениях         | Разграничение прав доступа                   |
| Системы автоматического аудита  | Контроль действий пользователей              |

## Обоснование необходимости защиты

- **Персональные и медицинские данные** — критичны для соответствия законодательству (152-ФЗ), поддержания доверия клиентов и предотвращения репутационных потерь.
- **Финансовые и кадровые данные** — необходимы для предотвращения мошенничества, финансовых потерь и соблюдения нормативных требований.
- **Технические и служебные данные** — важны для стабильности работы и предотвращения инсайдерских угроз.


---

## Необходимые действия для стратегии защиты данных в рамках всей системы

- Внедрить шифрование данных в покое и при передаче.
- Использовать автоматизированные системы контроля и аудита.
- Реализовать разграничение доступа и минимизацию выдаваемых данных.
- Регулярно проводить аудит и обновление политик безопасности.
